# Портфолио Татьяны Хлебко

Одностраничный сайт-портфолио SMM и контент-мейкера + резюме. Делается под конкретную
вакансию: помощник маркетолога по SMM и контенту в крюинговой компании (съёмка и монтаж
Reels/TikTok, визуалы, оформление постов по готовому контент-плану). Смотреть его будут
маркетолог и её руководитель Андрей.

Живой сайт: <https://mario-amazing.github.io/tatiana-portfolio/>
Репозиторий: `mario-amazing/tatiana-portfolio`, публичный, GitHub Pages из ветки `main`, корень `/`.

## Как всё устроено

Страница самодостаточна: шрифты, портрет и скриншот сайта вшиты как data URI, внешних
запросов нет вообще. Ролики — единственное исключение: они лежат отдельными файлами в
`clips/` и грузятся только по нажатию play (`preload="none"` + постер).

| Путь | Что |
|------|-----|
| `index.html` | собранная страница. **Руками не править** — пересобирается из шаблона |
| `build/template.html` | вся вёрстка и тексты, правки вносить сюда |
| `build/build.py` | сборка `index.html` |
| `build/assets/` | шрифты (Unbounded + Nunito), портрет, скриншот s53.by |
| `build/resume.md` | текст резюме, из него собирается docx |
| `clips/` | `m*` — массаж, `c*` — кондитерские, `o*` — другие ролики; к каждому `.mp4` есть `.jpg`-постер |
| `source/` | оригиналы из телеграма, **вне гита** (349 МБ) |

```bash
python3 build/build.py                 # пересобрать страницу
git add -A && git commit -m "…" && git push
pandoc build/resume.md -o ~/Desktop/tatiana-portfolio/Хлебко_Татьяна_SMM_контент.docx
```

Pages пересобирается сама за минуту-две, но может залипнуть на их сбоях — после пуша
дождаться, пока изменение реально появится на живом URL, и только потом отчитываться.

## Правила, оплаченные кровью

- **Скорость и частоту кадров роликов не трогать.** Приведение к 24 fps выглядит как
  ускорение, и это замечают сразу. Частоту кадров и длительность сохранять как в исходнике,
  обрезать ролики нельзя.
- **Жать только то, что тяжелее 30 МБ**, и жать слабо: исходное разрешение 1080x1920,
  подобрать CRF так, чтобы файл лёг чуть ниже 30 МБ, звук копировать (`-c:a copy`).
  Сейчас перекодированы четыре: `m2`, `c1`, `c2`, `o3`. Остальные — байт-в-байт оригиналы.
- **`m3` снят в HDR** (10 бит, HLG). При любом перекодировании ему нужен
  `format=gbrpf32le,tonemap=mobius,format=yuv420p`, иначе картинка выцветает.
- **`m4` в оригинале 720x1280**, не 1080 — он мягче соседних, и это свойство исходника,
  а не обработки. Не «чинить».
- **`doctype` и `viewport` обязательны.** Pages отдаёт файл как есть; без них телефон
  верстает страницу как десктопную и всё уменьшает.
- Проверять правки не на глаз: длительность и fps сверять через `ffprobe`, совпадение
  файла с оригиналом — по `shasum`, вёрстку — скриншотами headless Chrome (для настоящих
  390 px открывать страницу в `<iframe width="390">`, иначе headless зажимает окно до 500).
